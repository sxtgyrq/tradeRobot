# tradeRobot 需求文档

## 1. 项目背景

在一个二维坐标系中，交易所的位置固定为 `(0, 0)`。

系统需要在指定坐标范围内生成 `N` 个圆。坐标范围定义如下：

- `|x| <= 1000000`
- `|y| <= 1000000`

生成的圆需要同时满足边界约束和整体连通约束：每个圆必须完整位于指定坐标范围内，并且所有圆必须形成一个整体连通的圆集合。不能存在孤立圆，也不能生成彼此不连通的多组圆。

## 2. 核心需求

### 2.1 坐标系约束

- 坐标系为二维平面坐标系。
- 交易所坐标固定为 `(0, 0)`。
- 坐标范围为 `|x| <= MaxX`、`|y| <= MaxY`。
- 当前默认边界为 `MaxX = 1000000`、`MaxY = 1000000`。
- 默认生成圆数量为 `N = 10000`，该值作为可调整常量。

### 2.2 圆生成约束

- 系统需要生成 `N` 个圆。
- 每个圆应包含圆心坐标和带方向的半径信息。
- 圆数据由程序中的 `GenerateCircle()` 方法生成，并写入 `Circle.bin`。
- `Circle.bin` 不需要人工创建或手工编辑；如果文件已经存在，`GenerateCircle()` 应先读取已有圆数据，并在校验通过后按需补齐。
- 每条圆数据包含 `a`、`b`、`r`。
- `a`、`b`、`r` 的数据类型均为 `int`。
- `Circle.bin` 由 `N` 条圆记录组成，每条记录按 `a`、`b`、`r` 的顺序写入三个 `int`。
- 每条圆记录固定占用 `12` 字节，即 `3 * sizeof(int)`；已有 `Circle.bin` 的文件长度必须是 `12` 字节的整数倍。
- 圆的序号由生成顺序决定，`Circle.bin` 中记录顺序即圆的序号顺序。
- `(a, b)` 为圆心坐标，`r` 为带符号半径。
- `r > 0` 表示逆时针圆，即做多圆。
- `r < 0` 表示顺时针圆，即做空圆。
- `r` 不能为 `0`。
- `r = int.MinValue` 不属于支持范围，不能作为合法的带符号半径。
- 圆的几何半径记为 `R = abs(r)`。
- 圆的方程为 `(x - a)^2 + (y - b)^2 = R^2`。
- 生成结果中不能存在相同的几何圆，即不能存在相同的 `(a, b, R)`。
- 允许不同圆拥有相同的圆心坐标，只要它们的几何半径不同。
- 相同几何圆不允许以不同方向同时存在，即不能同时存在 `(a, b, r)` 和 `(a, b, -r)`。
- 圆的几何半径必须满足 `R >= 10`。
- 随机生成圆时，几何半径取值范围为 `10 <= R <= min(MaxX, MaxY)`。
- 圆必须完整位于指定坐标范围内。
- 对于任意圆，必须满足 `|a| + R <= MaxX` 且 `|b| + R <= MaxY`。
- 调用 `GenerateCircle(outputPath, count)` 时，`count` 不能小于基础圆数量 `2`。
- 任意一个圆都不能独立存在。
- 对于每一个圆，都必须至少存在另一个圆与它相交或相切。
- 所有圆必须属于同一个连通分量，不能拆分成两组或多组彼此不连通的圆集合。
- 如果一组圆与另一组圆之间不存在任何相交或相切关系，则该生成结果无效。

### 2.3 圆生成算法

圆数据由 `GenerateCircle()` 方法生成。当前默认调用方式为：

```text
GenerateCircle()
```

该方法会使用当前程序运行目录下的 `Circle.bin`，并以 `DefaultCircleCount = 10000` 作为目标数量。

内部可指定输出文件和目标数量：

```text
GenerateCircle(outputPath, count)
```

其中，`count` 表示目标圆数量，必须大于或等于 `2`。

#### 2.3.1 当 `Circle.bin` 不存在时

如果目标文件不存在，生成过程如下：

1. 先生成两个基础圆：
   - `a = -400000`，`b = 0`，`r = -499999`
   - `a = 400000`，`b = 0`，`r = 499999`
2. 两个基础圆本身必须满足边界约束，并且二者应存在圆周相交或相切关系。
3. 后续圆通过随机数生成 `a`、`b`、`r`。
4. 随机生成的圆必须完整位于整体坐标范围内。
5. 随机生成的圆不能与已有圆形成相同几何圆 `(a, b, R)`。
6. 随机生成的圆必须与已有圆集合中的至少一个圆存在圆周相交或相切关系。
7. 只有满足上述条件的随机圆才能加入圆集合。
8. 重复随机生成过程，直到圆数量达到 `count` 指定的数量；当前默认 `count = 10000`，后期可调整。

由于两个基础圆已经连通，并且每一个后续新增圆都必须与已有圆集合中的至少一个圆相交或相切，因此最终生成的所有圆应属于同一个连通分量。

#### 2.3.2 当 `Circle.bin` 已存在时

如果目标文件已经存在，生成过程如下：

1. 先读取已有 `Circle.bin` 中的圆记录。
2. 如果文件长度不是 `12` 字节的整数倍，则认为文件损坏，生成过程失败并报错。
3. 如果已有圆数量大于目标数量 `count`，生成过程失败并报错；系统不自动截断已有圆数据。
4. 如果已有文件为空，即已有圆数量为 `0`，则按“文件不存在”时的流程重新生成完整圆集合。
5. 如果已有文件不为空，则逐条校验已有圆：
   - 每个圆必须满足半径约束和坐标边界约束。
   - 不能存在重复几何圆 `(a, b, R)`。
   - 已有圆集合必须属于同一个连通分量。
6. 如果已有圆集合不能保持统一连通性，即拆分成两组或多组不连通圆集合，则生成过程失败并报错。
7. 如果已有圆数量小于 `count`，则保留已有圆及其顺序，并在此基础上继续随机生成新圆。
8. 每个新增圆仍必须满足边界约束、几何唯一性，并且必须与当前已有圆集合中的至少一个圆相交或相切。
9. 补齐到 `count` 后，需要再次确认最终圆集合属于同一个连通分量。
10. 校验和补齐完成后，程序将最终圆集合重新写回 `Circle.bin`。

已有 `Circle.bin` 中的圆不要求必须从两个基础圆开始；只要已有圆集合合法、几何唯一、整体连通且数量不超过 `count`，即可作为继续补齐的基础。

#### 2.3.3 随机生成失败处理

随机生成单个新增圆时，程序会多次尝试生成候选圆。候选圆只有同时满足边界约束、几何唯一性和与已有圆集合连通时才会被接受。

如果连续尝试达到上限仍无法生成合法候选圆，则生成过程失败并报错。

### 2.4 圆资金初始化

每个圆创建时，都会初始化自己的独立资金。

- 每个圆各自拥有初始资金 `10000`。
- 不同圆之间的初始资金相互独立，不共享、不合并。
- 如果生成 `N` 个圆，则系统初始总资金为 `N * 10000`，但业务计算仍以单个圆的独立资金为准。

### 2.5 圆扣费与破产重生

系统需要支持对当前坐标系中的每个圆收取费用。

- 每次扣费时，对每个圆收取 `100`。
- 扣费从该圆自身的独立资金中扣除。
- 不同圆之间不能互相代付扣费。
- 如果某个圆的可用金额不足以支付扣费，需要优先平仓该圆中风险高的合约，并使用平仓释放的金额支付扣费。
- 风险高的合约应优先处理；风险排序规则待进一步确认。
- 本轮从所有圆收取到的扣费，应汇总为本轮扣费池。
- 如果某个圆破产，则该圆从坐标系中抹去。
- 圆被抹去后，系统需要新生成一个圆，用于补齐圆的数量。
- 新生成的圆必须满足前文定义的圆生成约束，包括坐标边界、几何半径限制、`(a, b, R)` 唯一性和非孤立约束。
- 破产后新生成的圆定义为奖励圆，奖励圆的初始金额为 `100`。
- 新圆生成完成后，需要将本轮扣费池平均分配给当前坐标系中的每个圆。
- 如果当前坐标系中共有 `N` 个圆，则每个圆获得的分配金额为 `本轮扣费池 / N`。

圆发生破产重生后，系统需要重新计算所有派生数据：

- 路径点。
- 末尾联通点。
- 普通联通点。
- 采购点。
- 收割点。
- 采购点到收割点的可达性。

扣费触发时机和破产判定规则待进一步确认。

### 2.6 圆分段规则

对于任意一个圆，需要根据该圆的几何半径 `R` 计算分段数量。

为避免与圆的总数量 `N` 混淆，单个圆的分段数量记为 `n`。计算公式如下：

```text
n = floor(2 * π * R) * M + 1
```

其中：

- `R` 表示当前圆的几何半径，即 `R = abs(r)`。
- `π` 表示圆周率。
- `floor` 表示向下取整。
- `M` 表示路径点密度倍数，当前默认 `M = 300`，后期可作为常量调整。
- `n` 表示该圆需要被划分的份数。
- `n` 必须小于或等于 `int.MaxValue`；如果计算结果超过 `int.MaxValue`，系统应直接报错。

计算出 `n` 后，应将整个圆划分为 `n` 份圆弧，并生成 `n` 个路径点。

由于 `M` 较大，路径点数量可能非常多。实现时不要求一次性枚举或实体化保存所有路径点；允许根据圆序号、路径点编号和计算公式按需惰性计算路径点坐标。

划分时，以圆上的极点作为起点。这里的极点指圆上 `x` 坐标最大的点，即 `(a + R, b)`。

圆的分段方向由带符号半径 `r` 决定：

- 当 `r > 0` 时，从极点 `(a + R, b)` 开始，沿逆时针方向依次划分圆。该圆定义为做多圆。
- 当 `r < 0` 时，从极点 `(a + R, b)` 开始，沿顺时针方向依次划分圆。该圆定义为做空圆。

圆被划分后得到的圆上点，统一定义为路径点。路径点按当前圆的分段方向从极点开始依次编号，编号范围为 `0` 到 `n - 1`，不额外生成与极点重复的终点。

收割点与采购点统称为交易点。除交易点以外的其他路径点，统称为流通点。

路径点 `n - 1` 定义为该圆的末尾联通点。末尾联通点用于表示该圆路径序列的末尾，并按照当前圆允许的路径方向单向连接回路径点 `0`。末尾联通点是路径点的一种特殊状态，但不属于圆间连通关系产生的普通联通点。

末尾联通点具有以下限制：

- 可以作为普通路径点参与圆内路径行走。
- 不能被选为收割点。
- 不能作为圆间连通关系中的普通联通点。
- 不能作为采购点。

除末尾联通点以外，由圆间相交或相切关系产生的路径点，定义为普通联通点。普通联通点之间的圆间连通关系是双向的；末尾联通点只负责同一个圆内从 `n - 1` 到 `0` 的单向连通。

### 2.7 路径点角色编码

为了便于后续存储、调试和路径计算，路径点应支持角色编码。

派生点计算完成后，需要按 `(circleIndex, pointIndex)` 查找位置相同的点。若两个点的 `circleIndex` 和 `pointIndex` 均相等，则认为它们是同一个路径点上的不同角色，应删除旧的两条点记录，并合并为一条新点记录。新点的 `circleIndex` 和 `pointIndex` 保持不变，`pointType` 为两个旧点 `pointType` 的乘积。

若同一个路径点后续仍有更多角色需要合并，则继续按相同规则累乘 `pointType`。由于当前占用型角色互斥，实际允许叠加的典型情况是“第一路径点”标记叠加一个占用型角色。

路径点角色编码如下：

```text
普通路径点             = 1
收割点                 = 2
每个圆的第一个路径点   = 3
末尾联通点             = 5
普通联通点             = 7
采购点                 = 11
```

其中：

- 普通路径点编码为 `1`，表示该路径点没有任何特殊角色。
- 收割点是全局唯一路径点。
- 每个圆的第一个路径点指路径点编号为 `0` 的点。
- 末尾联通点指路径点编号为 `n - 1` 的点。
- 普通联通点指参与圆间双向连通关系的路径点。
- 采购点指分配给某个圆的采购路径点。

当一个路径点同时具备多个角色时，应先生成各自角色点，再按相同位置合并为合数编码。例如：

```text
第一个路径点同时是收割点：2 * 3 = 6
第一个路径点同时是普通联通点：7 * 3 = 21
第一个路径点同时是采购点：11 * 3 = 33
```

角色判断方式为取模判断：

```text
编码 % 2 == 0  表示该路径点是收割点
编码 % 3 == 0  表示该路径点是每个圆的第一个路径点
编码 % 5 == 0  表示该路径点是末尾联通点
编码 % 7 == 0  表示该路径点是普通联通点
编码 % 11 == 0 表示该路径点是采购点
```

角色限制仍以各角色定义为准：

- 末尾联通点不能是收割点、普通联通点或采购点。
- 普通联通点不能是收割点，也不能是末尾联通点。
- 采购点不能是收割点、普通联通点或末尾联通点。
- 收割点、末尾联通点、普通联通点、采购点属于占用型角色；同一个路径点最多只能拥有一个占用型角色。
- 同类型占用也必须唯一：收割点全局唯一；一个路径点最多参与一条普通联通关系；一个路径点最多被一个圆选为采购点。
- 每个圆的第一个路径点只是路径点编号为 `0` 的标记，不属于占用型角色。
- 第一个路径点可以同时带有“第一个路径点”标记和一个占用型角色，但不能同时拥有两个或多个占用型角色，也不能被两个普通联通关系重复占用。

因此，路径点编号为 `0` 的第一个路径点可以叠加收割点、普通联通点或采购点中的任意一个角色；路径点编号为 `n - 1` 的末尾联通点不能叠加收割点、普通联通点或采购点角色。

路径点角色编码主要用于标记路径点状态，不改变路径点编号、圆内行走方向和圆间连通关系的计算规则。合并后的 `pointType` 可以是质数，也可以是多个质数相乘得到的合数。

### 2.8 派生点计算顺序与格式

在圆生成完成后，系统应按固定顺序计算所有派生点。计算顺序如下：

```text
A. 全场唯一收割点
B. 所有圆的第一路径点
C. 所有圆的末尾联通点
D. 所有普通联通点
E. 所有采购点
```

该顺序必须保持稳定。后续步骤在选择路径点时，应遵守前序步骤已经产生的占用型角色约束。

所有需要输出或存储的特殊路径点，统一使用以下格式：

```text
(circleIndex, pointIndex, pointType)
```

其中：

- `circleIndex` 表示圆序号，从 `0` 开始，对应 `Circle.bin` 中的记录顺序。
- `pointIndex` 表示该点在当前圆上的路径点序号，从 `0` 开始。
- `pointType` 表示路径点角色编码，使用“路径点角色编码”章节定义的质数或质数乘积编码。

例如：

```text
(3, 0, 3)
```

表示圆序号为 `3` 的第一个路径点。

```text
(3, 0, 6)
```

表示圆序号为 `3` 的同一个路径点同时是全场唯一收割点和第一个路径点；合并后输出一条合数编码记录。

计算各类派生点时，应保证收割点、末尾联通点、普通联通点、采购点这些占用型角色互斥。同一个路径点不能被两个占用型角色共同占用，也不能被同类型角色重复占用。

涉及“距离最近”的点选择时，如果存在距离相同的并列结果，需要使用稳定排序规则：

- 如果候选点来自同一个圆，则选择路径点编号最小的点。
- 如果候选点来自不同圆，则先选择圆序号最小的点；圆序号相同时，再选择路径点编号最小的点。

#### 2.8.1 CUDA 点集数组格式

派生点完成计算并按 `(circleIndex, pointIndex)` 合并后，需要形成可传入 CUDA 计算的连续 `int[]` 数组。

CUDA 点集数组只保存合成后的点集信息，不保存路径点坐标，也不保存圆的 `a`、`b`、`r` 参数。

数组格式如下：

```text
int[] cudaPoints = [circleIndex, pointIndex, pointType, ...]
```

每 `3` 个连续的 `int` 表示一个合成后的派生点：

```text
cudaPoints[i * 3 + 0] = circleIndex
cudaPoints[i * 3 + 1] = pointIndex
cudaPoints[i * 3 + 2] = pointType
```

其中：

- `circleIndex` 表示圆序号。
- `pointIndex` 表示路径点在该圆上的序号。
- `pointType` 表示合并后的路径点角色编码，可以是质数，也可以是多个质数相乘得到的合数。

点数量计算方式为：

```text
pointCount = cudaPoints.Length / 3
```

例如合成后的点集为：

```text
(0, 0, 6)
(0, 18600, 5)
(0, 1, 11)
```

则对应的 CUDA 点集数组为：

```text
[0, 0, 6, 0, 18600, 5, 0, 1, 11]
```

CUDA 计算中如需路径点坐标，应通过 `circleIndex` 找到对应圆，再结合 `pointIndex` 按路径点公式反推坐标；`cudaPoints` 本身不存储坐标。

#### 2.8.2 CUDA 传参前数据准备规则

在调用 CUDA 计算函数之前，CPU 侧必须先完成派生点整理、点集排序、数组构建和基础一致性校验。

CUDA 传参前的数据准备顺序如下：

```text
1. 生成派生点数据，得到合并后的点集和普通联通关系。
2. 将合并后的点集按 circleIndex、pointIndex、pointType 升序排序。
3. 按排序后的点集构建 cudaPoints。
4. 按排序后的点集和普通联通关系构建 connect。
5. 从排序后的点集中提取交易点 tradingPoints。
6. 按本次并行起点数量构建 lastFP。
7. 将 cudaPoints、connect、lastFP 等数组传入 CUDA 计算函数。
```

排序后的点集顺序定义为 CUDA 点序号。设排序后的第 `i` 个点为：

```text
points[i] = (circleIndex, pointIndex, pointType)
```

则它在 `cudaPoints` 中的位置为：

```text
cudaPoints[i * 3 + 0] = circleIndex
cudaPoints[i * 3 + 1] = pointIndex
cudaPoints[i * 3 + 2] = pointType
```

因此，所有依赖点序号的辅助数组都必须使用同一套排序后的点序号，不能使用圆内 `pointIndex` 代替 CUDA 点序号。

在传入 CUDA 前，必须校验以下数量关系：

- 收割点数量必须等于 `1`。
- 采购点数量必须等于圆数量。
- 第一路径点数量必须等于圆数量。
- 末尾联通点数量必须等于圆数量。
- 如果上述数量关系不成立，说明派生点计算或合并逻辑错误，系统应直接报错，不得继续调用 CUDA。

`connect` 用于描述 CUDA 点集中的特殊跳转关系，其长度必须等于 CUDA 点数量：

```text
int[] connect
connect.Length = cudaPoints.Length / 3
```

`connect[i]` 表示排序后第 `i` 个 CUDA 点的特殊跳转目标点序号：

- `connect[i] = -1` 表示该 CUDA 点没有特殊跳转关系。
- `connect[i] = j` 表示排序后第 `i` 个 CUDA 点可以直接跳转到排序后第 `j` 个 CUDA 点。
- 如果 CUDA 内部需要访问目标点三元组，则目标点在 `cudaPoints` 中的起始位置为 `j * 3`。

`connect` 只保存特殊跳转关系，不保存普通圆内行走关系。普通圆内行走关系应根据圆方向和 `pointIndex` 计算；末尾联通点和普通联通点才写入 `connect`。

`connect` 的构建规则如下：

- 初始时，`connect` 中所有元素均为 `-1`。
- 对于 `pointType % 5 == 0` 的末尾联通点，`connect` 应单向指向同一个圆的第一路径点，即同一 `circleIndex` 下 `pointIndex = 0` 的点。
- 对于 `pointType % 7 == 0` 的普通联通点，应依据普通联通关系成对建立双向跳转：左侧点指向右侧点，右侧点指向左侧点。
- 普通路径点、收割点、第一路径点、采购点本身不因为自身角色写入 `connect`；如果它们没有同时叠加末尾联通点或普通联通点角色，则对应 `connect` 保持 `-1`。

构建 `connect` 时必须进行严格校验：

- 合并后的点集中不允许存在重复的 `(circleIndex, pointIndex)`；如果存在，应直接报错。
- 末尾联通点必须能找到同圆的第一路径点；如果找不到，应直接报错。
- 普通联通关系中的两个端点都必须能在排序后的点集中找到；如果找不到，应直接报错。
- 同一个 CUDA 点不能被分配到两个不同的 `connect` 目标；如果发生冲突，应直接报错。

交易点 `tradingPoints` 是 CUDA 路径计算中的起点或终点候选。交易点由排序后的 CUDA 点序号组成，不保存圆内 `pointIndex`：

```text
pointType % 2 == 0  表示收割点
pointType % 11 == 0 表示采购点
```

满足上述任一条件的点都应加入 `tradingPoints`。因此，`tradingPoints` 中保存的是排序后的点序号 `i`，对应的点数据位于 `cudaPoints[i * 3]` 开始的三个 `int`。

`parallelStartPointCount` 表示一次 CUDA 并行计算多少个起点。构建 `lastFP` 时，应按当前批次的起点数量和交易点数量初始化：

```text
lastFP.Length = tradingPoints.Count * parallelStartPointCount
```

`lastFP` 默认值为 `-1`。对于当前批次中的每一个起点，应在对应位置写入该起点的 CUDA 点序号，用于表示该起点当前路径的最后一个地址。`lastFP` 中保存的值同样是排序后的 CUDA 点序号，而不是圆内 `pointIndex`，也不是 `cudaPoints` 的字节偏移或三元组偏移。

### 2.9 路径行走规则

路径点之间沿圆周移动时，必须遵守对应圆的旋转方向：

- 做多圆上的路径点，路径只能按照逆时针方向行走。
- 做空圆上的路径点，路径只能按照顺时针方向行走。

### 2.10 圆相交判定

两个圆是否相交，应根据圆心距离与两个圆的几何半径之间的关系判断。

设两个圆分别为：

- 圆 A：圆心 `(x1, y1)`，带符号半径 `r1`，几何半径 `R1 = abs(r1)`
- 圆 B：圆心 `(x2, y2)`，带符号半径 `r2`，几何半径 `R2 = abs(r2)`

设两个圆的圆心距离为 `d`。只有圆周相交或相切时，才认为两个圆存在连接关系：

```text
abs(R1 - R2) <= d <= R1 + R2
```

其中：

- `abs(R1 - R2) < d < R1 + R2` 表示两个圆圆周相交，有两个交点。
- `d = R1 + R2` 表示两个圆外切，有一个交点。
- `d = abs(R1 - R2)` 表示两个圆内切，有一个交点。

如果一个圆完全包含另一个圆，但两条圆周没有交点，即 `d < abs(R1 - R2)`，则不算相交，也不算联通。

相切也算满足非孤立约束。

### 2.11 不同圆之间的连通关系

对于任意两个不同的圆，如果它们相交或相切，需要计算两个圆的交点。

只有在两个圆的圆周相交或相切时，才允许建立圆间连通关系。不相交、不相切的两个圆不能建立连通关系。

- 如果两个圆相交，通常会得到两个交点。
- 如果两个圆相切，则只会得到一个交点。

对于每一个交点，需要分别在两个圆的路径点中寻找距离该交点最近的可用路径点：

- 在圆 A 自身的路径点中，找到距离该交点最近的可用路径点，记为 `PA`。
- 在圆 B 自身的路径点中，找到距离该交点最近的可用路径点，记为 `PB`。
- 路径点必须来自当前这两个相交或相切的圆本身，不能使用第三个圆上的路径点。
- 可用路径点不能是全局唯一的收割点。
- 可用路径点不能是该圆的末尾联通点，即路径点编号不能为 `n - 1`。
- 可用路径点不能已经参与过其他圆间连通关系，不能已经是普通联通点。
- 如果最近路径点存在并列，则按照路径点编号最小原则选择。

`PA` 与 `PB` 之间建立一条双向连通关系。

参与该圆间连通关系的两个点，统一定义为普通联通点。

一个路径点最多只能参与一条圆间连通关系。一旦某个路径点参与了圆间连通关系，它就被标记为普通联通点，并视为已被联通关系占用；后续其他圆间连通关系不能再选择该路径点。

普通联通点不能是收割点，也不能是末尾联通点。

因此，两个圆之间的连通关系最终体现为两个圆上的普通联通点之间的双向连通关系。如果两个圆有两个交点，则必须分别针对两个交点建立两条路径点连通关系；如果两个圆相切，只有一个交点，则按相同规则建立一条路径点连通关系。

如果某个交点在任意一个相关圆上找不到可用路径点，或者任意一条必须建立的圆间连通关系无法建立，则普通联通点计算失败，系统应直接报错。

普通联通点来源于路径点，但路径点不一定都是普通联通点。只有参与圆间连通关系的路径点，才被视为普通联通点。

在计算普通联通点时，如果因为路径点已被占用、路径点为收割点、路径点为末尾联通点等原因导致可用路径点数量不足，系统应直接报错，不得跳过交点，也不得降级为少建普通连通关系。

### 2.12 禁区点规则取消

系统不再定义禁区点。

路径点到原点 `(0, 0)` 的距离不再形成特殊状态。也就是说，以下条件不再用于标记任何路径点：

```text
sqrt(x^2 + y^2) <= 100
```

因此，系统不再要求生成结果中必须存在禁区点。原先需要排除禁区点的位置，统一改为排除全局唯一的收割点。

### 2.13 采购点定义

采购点需要满足唯一占用规则：

- 每个圆必须分配一个采购点。
- 每个采购点最多只能被一个圆占用。
- 圆在选择采购点时，只能选择尚未被占用的路径点。

实际计算时，应先确定全局唯一的收割点，再分配采购点。

采购点候选必须可达全局唯一的收割点。原则上，在不存在孤立圆且联通关系正确建立时，采购点候选应当能够到达收割点；系统仍需要在分配采购点时进行可达性校验。

在所有路径点中，排除收割点、普通联通点、末尾联通点、已被采购点占用的路径点，以及无法到达收割点的路径点后，剩余路径点可以作为当前圆的采购点候选。

采购点按圆的生成顺序依次分配。对于当前圆，以该圆的圆心为目标点，在当前可用的采购点候选中寻找距离该圆圆心最近的路径点。该路径点定义为这个圆的采购点。选中后，该路径点被标记为已占用，不能再被其他圆选为采购点。如果最近候选点存在并列，则按照通用并列排序规则选择。

设圆的圆心为 `C(a, b)`，候选路径点为 `P(x, y)`，则距离计算方式为：

```text
distance(C, P) = sqrt((x - a)^2 + (y - b)^2)
```

对每个圆，应在当前可用的采购点候选中，选择 `distance(C, P)` 最小的路径点作为该圆的采购点。

采购点来源于路径点，但采购点不能是收割点、普通联通点，也不能是末尾联通点。

如果某个圆在分配采购点时找不到任何可用路径点，则系统应直接报错。

### 2.14 收割点定义

收割点是全局唯一的点。

在所有路径点中，寻找距离原点 `(0, 0)` 最近且不是末尾联通点的路径点。该路径点定义为收割点。

设路径点为 `P(x, y)`，则该路径点到原点的距离计算方式为：

```text
distance(O, P) = sqrt(x^2 + y^2)
```

应选择 `distance(O, P)` 最小且不是末尾联通点的路径点作为收割点。

收割点来源于路径点，但不能是末尾联通点。

如果不存在可用的非末尾联通点路径点，则无法确定收割点，系统应直接报错。

任何需要选择路径点的计算，如果候选路径点不足以满足当前规则，都应直接报错，不做跳过、降级或自动放宽限制处理。

### 2.15 采购点到收割点的可达性

每个采购点都必须能够通过路径点、末尾联通点和普通联通点，最终到达全局唯一的收割点。

路径可达性需要遵守以下规则：

- 在同一个圆内，只能沿该圆允许的路径方向移动。
- 做多圆只能沿逆时针方向移动。
- 做空圆只能沿顺时针方向移动。
- 当路径到达普通联通点时，可以通过双向圆间连通关系移动到另一个圆上对应的普通联通点。
- 当路径到达末尾联通点时，只能沿该圆的单向末尾连通关系移动到同一个圆的路径点 `0`。
- 经过若干路径点、末尾联通点和普通联通点后，最终必须能够到达收割点。

### 2.16 全局路径可达性

在满足以下条件时，系统应保证从收割点可以到达任意路径点：

- 所有圆属于同一个连通分量。
- 每个圆的路径点按该圆允许方向形成闭环，其中末尾联通点 `n - 1` 单向连接回路径点 `0`。
- 不同圆之间的普通联通关系是双向的。
- 收割点来源于路径点。

由于圆内路径通过末尾联通点形成有向闭环，即使只能沿单一方向行走，也可以在同一个圆内到达该圆上的任意路径点。再结合双向普通联通关系和整体连通约束，从全局唯一的收割点出发，应能到达任意圆上的任意路径点。

### 2.17 收割点与采购点的往返路径

在完成路径点、末尾联通点、普通联通点、采购点和收割点计算后，系统需要计算收割点与每个采购点之间的路径距离。

对于每个采购点，都需要分别计算：

- 收割点到该采购点的距离。
- 该采购点到收割点的距离。

由于做多圆和做空圆存在路径行走方向限制，收割点到采购点的路径距离与采购点到收割点的路径距离需要分别计算，二者不要求相等。

对于每个采购点，系统都应生成一条完整路径：

```text
收割点 -> 采购点 -> 收割点
```

该路径由两段组成：

- 第一段：从收割点出发，到达采购点。
- 第二段：从采购点出发，返回收割点。

两段路径都必须遵守路径行走规则和联通关系规则。

### 2.18 做多尺度规则

当 `收割点 -> 采购点 -> 收割点` 的完整路径经过做多圆时，系统需要根据路径在该做多圆上的累计弧度，决定做多的尺度。

累计弧度表示路径在当前做多圆上，沿做多圆允许方向已经累计经过的圆心角大小。

- 做多圆的允许方向为逆时针方向。
- 路径经过做多圆时，只统计沿该做多圆逆时针方向经过的弧度。
- 做多尺度由累计弧度决定。

做多规则如下：

```text
杠杆倍数 = 35
做多保证金 = min(1, θ / 2π) / 100 * 可使用金额
做多名义仓位 = 做多保证金 * 35
止盈价 = 当前路过金额 * 46 / 45
```

其中：

- `θ` 表示路径在当前做多圆上的累计弧度。
- `可使用金额` 表示当前可用于开多的金额。
- `当前路过金额` 表示路径经过当前点时对应的金额。

### 2.19 做空尺度规则

当 `收割点 -> 采购点 -> 收割点` 的完整路径经过做空圆时，系统需要根据路径在该做空圆上的累计弧度，决定做空的尺度。

累计弧度表示路径在当前做空圆上，沿做空圆允许方向已经累计经过的圆心角大小。

- 做空圆的允许方向为顺时针方向。
- 路径经过做空圆时，只统计沿该做空圆顺时针方向经过的弧度。
- 做空尺度由累计弧度决定。

做空规则如下：

```text
杠杆倍数 = 35
做空保证金 = min(1, θ / 2π) / 100 * 可使用金额
做空名义仓位 = 做空保证金 * 35
止盈价 = 当前路过金额 * 45 / 46
```

其中：

- `θ` 表示路径在当前做空圆上的累计弧度。
- `可使用金额` 表示当前可用于开空的金额。
- `当前路过金额` 表示路径经过当前点时对应的金额。

### 2.20 补充保证金规则

做多或做空过程中，如果仓位接近爆仓，系统需要补充保证金。

- 补充保证金从对应圆的可使用金额中扣除。
- 补充保证金后，对应圆的可使用金额减少。
- 补充保证金后，该仓位的保证金增加。
- 补充保证金用于降低仓位爆仓风险。

接近爆仓的判定规则和补充保证金的金额计算规则待进一步确认。

## 3. 验收标准

- 能够生成指定数量 `N` 的圆；当前默认 `N = 10000`，且该值可作为常量调整。
- 每个圆都包含合法的圆心坐标和带方向的半径信息。
- 生成结果应由 `GenerateCircle()` 方法写入 `Circle.bin`，文件包含 `N` 条记录，每条圆数据按 `a`、`b`、`r` 顺序写入三个 `int`。
- 如果 `Circle.bin` 已存在，`GenerateCircle()` 应先读取已有圆数据；已有圆数据合法且数量不足时，应在保持整体连通的前提下补齐到目标数量。
- 如果已有 `Circle.bin` 的长度不是 `12` 字节的整数倍，应判定为文件损坏并报错。
- 如果已有圆数量大于目标数量，系统应报错，不自动截断已有数据。
- 如果已有圆数据违反边界约束、半径约束、几何唯一性或整体连通约束，系统应报错。
- `r > 0` 的圆应定义为做多圆，`r < 0` 的圆应定义为做空圆。
- `r` 不能为 `0`，且 `r = int.MinValue` 不属于合法输入范围。
- 生成结果中不能存在相同的几何圆 `(a, b, R)`；允许圆心坐标相同但几何半径不同的圆同时存在。
- 每个圆的几何半径满足 `R = abs(r) >= 10`。
- 随机生成圆的几何半径应满足 `10 <= R <= min(MaxX, MaxY)`。
- 每个圆都完整位于指定坐标范围内。
- 每个圆创建时，都应拥有独立的初始资金 `10000`。
- 每次扣费时，每个圆应从自身独立资金中扣除 `100`。
- 当圆的可用金额不足以支付扣费时，应优先平仓该圆中风险高的合约，并使用平仓释放的金额支付扣费。
- 破产圆应从坐标系中抹去，并由系统新生成一个符合所有圆生成约束的圆补齐数量。
- 破产后新生成的奖励圆初始金额应为 `100`。
- 新圆生成完成后，应将本轮收取到的扣费平均分配给当前坐标系中的每个圆。
- 圆破产重生后，应重新计算所有路径点、末尾联通点、普通联通点、采购点、收割点和采购点到收割点的可达性。
- 每个圆都能按照 `n = floor(2 * π * R) * M + 1` 计算分段数量，默认 `M = 300`，并从圆上 `x` 最大的点开始，按 `r` 的符号对应方向划分为 `n` 份。
- 单个圆的路径点数量 `n` 必须小于或等于 `int.MaxValue`；超过时系统应直接报错。
- `r > 0` 的圆应按逆时针方向划分并定义为做多圆，`r < 0` 的圆应按顺时针方向划分并定义为做空圆。
- 圆被划分为 `n` 份圆弧后，应生成 `n` 个路径点；路径点按当前圆方向从极点开始编号，不生成重复终点。
- 收割点与采购点统称为交易点；除交易点以外的其他路径点统称为流通点。
- 每个圆的路径点 `n - 1` 应定义为末尾联通点；末尾联通点只能单向连接回同一个圆的路径点 `0`。
- 末尾联通点不能是收割点、普通联通点或采购点。
- 路径点应支持角色编码：普通路径点 `1`，收割点 `2`，每个圆的第一个路径点 `3`，末尾联通点 `5`，普通联通点 `7`，采购点 `11`；同一路径点具备多个角色时，先按角色生成点，再按 `(circleIndex, pointIndex)` 合并位置相同的点，合并后 `pointType` 为各角色编码的乘积。
- 收割点、末尾联通点、普通联通点、采购点为占用型角色，同一个路径点最多只能拥有一个占用型角色；第一个路径点只是编号为 `0` 的标记，可以叠加一个占用型角色，但不能叠加多个占用型角色。
- 派生点应按顺序计算：全场唯一收割点、所有圆的第一路径点、所有圆的末尾联通点、所有普通联通点、所有采购点；所有输出点格式统一为 `(circleIndex, pointIndex, pointType)`。
- 合并后的派生点集应能转换为 CUDA 使用的连续 `int[] cudaPoints`，格式固定为 `[circleIndex, pointIndex, pointType, ...]`，每 `3` 个 `int` 表示一个点；该数组只保存点集信息，不保存坐标或圆参数。
- 调用 CUDA 计算函数前，必须将合并后的派生点按 `circleIndex`、`pointIndex`、`pointType` 升序排序；排序后的点序号即 CUDA 点序号，`cudaPoints[i * 3]` 对应第 `i` 个 CUDA 点。
- 调用 CUDA 计算函数前，必须构建 `connect` 数组；`connect.Length = cudaPoints.Length / 3`，默认值为 `-1`，末尾联通点单向指向同圆第一路径点，普通联通点按普通联通关系双向互指，其他点保持 `-1`。
- 构建 `connect` 时，如果存在重复 `(circleIndex, pointIndex)`、缺失跳转目标或同一 CUDA 点被分配到不同跳转目标，系统应直接报错，不得继续调用 CUDA。
- 调用 CUDA 计算函数前，应从排序后的 CUDA 点序号中提取交易点 `tradingPoints`；`pointType % 2 == 0` 或 `pointType % 11 == 0` 的点均属于交易点。
- 调用 CUDA 计算函数前，应按 `parallelStartPointCount` 和 `tradingPoints.Count` 构建 `lastFP`；`lastFP` 默认值为 `-1`，其中写入的地址必须是排序后的 CUDA 点序号。
- 做多圆上的路径点只能按照逆时针方向行走，做空圆上的路径点只能按照顺时针方向行走。
- 生成结果中不存在孤立圆。
- 任意一个圆都能找到至少一个与其相交或相切的其他圆。
- 所有圆必须形成一个整体连通的圆集合，不能出现两组或多组彼此不连通的圆。
- 对于相交或相切的两个圆，能够根据交点分别在这两个圆自身的路径点中找到最近的可用路径点，并在这两个路径点之间建立双向普通连通关系。
- 圆间连通关系只能在相交或相切的两个圆之间建立，不能使用第三个圆的路径点。
- 圆间相交得到两个交点时，必须分别建立两条普通连通关系；相切只有一个交点时，建立一条普通连通关系。
- 如果普通联通点计算中可用路径点不足，系统应直接报错，不得跳过交点或少建普通连通关系。
- 一个路径点最多只能参与一条圆间连通关系；已经成为普通联通点的路径点，不能被后续连通关系再次占用。
- 普通联通点不能是全局唯一的收割点，也不能是末尾联通点。
- 参与圆间连通关系的两个点，应被标记为普通联通点；路径点不一定都是普通联通点。
- 系统不再定义禁区点，也不再要求禁区点数量。
- 收割点必须从所有路径点中选择距离原点 `(0, 0)` 最近的点，但不能选择末尾联通点；如果不存在可用收割点，系统应报错。
- 采购点应按圆的生成顺序依次分配；对于每个圆，应在所有未被占用、非收割点、非普通联通点、非末尾联通点、且能够到达收割点的路径点中，找到距离该圆圆心最近的路径点，并将其标记为该圆的采购点。
- 如果某个圆找不到可用采购点，系统应直接报错。
- 每个采购点最多只能被一个圆占用。
- 距离最近的路径点存在并列时，应按照圆序号和路径点编号的稳定排序规则选择。
- 应在所有路径点中，找到距离原点 `(0, 0)` 最近且不是末尾联通点的路径点，并将其标记为全局唯一的收割点。
- 在整体连通、圆内有向闭环、普通联通关系双向的前提下，从收割点应能够到达任意路径点。
- 每个采购点都必须能够通过路径点、末尾联通点和普通联通点，最终到达收割点。
- 对于每个采购点，应分别计算收割点到采购点的距离，以及采购点到收割点的距离。
- 对于每个采购点，应生成 `收割点 -> 采购点 -> 收割点` 的完整路径。
- 当完整路径经过做多圆时，应能够根据路径在该做多圆上的累计弧度 `θ` 计算做多保证金、做多名义仓位和止盈价。
- 当完整路径经过做空圆时，应能够根据路径在该做空圆上的累计弧度 `θ` 计算做空保证金、做空名义仓位和止盈价。
- 做多或做空仓位接近爆仓时，应能够从对应圆的可使用金额中补充保证金。
